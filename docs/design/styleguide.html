State semantics

Four states, each meaning exactly one thing anywhere in the app. Milestone deliberately equals the header colour — that shared value is what makes a checkpoint read as an event rather than another card.

Tone colours data, not theme

These live in the TONES object in app.js, not in the token block. They are content, applied per-syllable by colorJyutping(), and are deliberately excluded from the theme so a palette swap never changes them.

Two weights only. 1px hairline at rest, everywhere. 3px --edge-emph left rule to mark one thing as significant — used for next-up steps, checkpoint cards, and the quiz teaching panel. Motion & tap targets

Transitions use --dur-fast (120ms) for state flips and --dur-base (200ms) for anything entering or leaving, both on --ease. Every interactive element is at least --tap-min (44px) in its smaller dimension — including header icons, which is a rule my earlier mockups broke.

.btn-icon — 44 × 44, 15px glyph

Painted size and touch target are separate things. --tap-min governs what responds to a thumb, not what is drawn. A control may paint smaller and still carry a full-size hit area, via a centred pseudo-element that takes no part in layout. That is what .btn-icon--compact does: 32px painted, 44px tappable.

Two painted sizes for circular controls, and no more. Before this rule the play/mic control existed at seven sizes across the app — 28, 32, 34, 38, 38, 40 and 44px — six of them below the minimum. Settled in docs/design/15-control-vocabulary.html.

.btn-icon--brand — 44px standard + --compact — 32px painted, 44px target

The two corner controls are not the same width — the info button is 44px, the hamburger 36px — so each sits in a fixed --tap-min slot and the plate centres on the row rather than on the space the icons happen to leave. Nameplate type is deliberately untouched: size, weight and face wait on the product-naming decision, which gates the logo.

The nameplate is a route Home (DES-18, built v116). It is a <button> that hugs its text rather than filling the centre slot — ~128px of wordmark, not ~238px of mostly-blank band, because an invisible full-width target on a sticky header catches stray thumbs mid-scroll. Nothing marks it at rest: a wordmark centred between two corner icons reads as a logo slot, and a logo goes home. Pressing drops its opacity, the same language the corner icons already use. This page previously used .nameplate as a local demo class meaning something unrelated; it is now .sg-plate, since the name belongs to a real component.

Subtabs & tab bar subtabs built · v114 --top not built · phase 6

One primitive, two consumers. The topic's view switch (Learn / Chat / Quiz) and the bottom tab bar carry the same emphasis language: muted label, brand label when active, and a 2px brand rule on the edge nearest the content — bottom for the subtabs, top for the bar.

The edge is not the only difference, and this note said it was until v114 while the CSS beside it always disagreed. --top also flips the axis to a column, and changes the gap, the padding, the icon size and the label's whole type scale — 9.5px uppercase over a 19px glyph, against 14px beside a 15px one. What the two consumers genuinely share is the emphasis language, not the geometry, and that is enough to make them one primitive. The modifier sits on the container (.tabs--top) rather than the tab, so it can reach both.

An active tab is never a fill (DES-19). A tab is a selector, not an action, and the screen's one filled element belongs to the thing to do next. The pre-system subtabs were three separately bordered boxes with a solid brand fill on the active one, which made the view switch the loudest thing on the Learn screen — visible in the app through v113.

Equal widths (MOCK-17-fill), chosen over mockup 04's left-packed geometry: the tab bar has no choice, since it carries five destinations across the viewport, and matching it is what makes these one primitive rather than two that resemble each other. Geometry is where a shared language drifts apart first.

Settings sheet built · v117

Behind the header cog, not in the tab bar. Tabs hold destinations, not features (DES-11) — this is where anything occasional lives, and where account and subscription go later. The cog lights while the sheet is open because it is the sheet's origin, not because settings is somewhere you now are; it never takes an active state the way a tab does.

Sized to its contents, not to the viewport (MOCK-19-sheet). It holds one setting today — audio speed — and a full-height surface would only advertise that. When account and subscription arrive it becomes a full screen by changing the wrapper: the .set-row markup inside is the same either way, so nothing here has to be rebuilt to get there. Opening pushes a history entry, so phone BACK closes the sheet rather than leaving the screen underneath, and the × and the scrim both route through that same step-back.

State semantics

StateTokenMeansUsed by
Current--brandThe thing to do nextNext-up step, active tier, active subtab, primary button
Done--jade / --feedback-goodFinishedCompleted steps, correct answers, completion ticks
Milestone--milestoneA checkpoint — an event, not a lessonCheckpoint nodes, cards, hub, diamond progress
Error--feedback-badA wrong answerQuiz choices, quiz review rows

Nothing else gets a colour. If a new UI element seems to need a fifth state, the likelihood is it's one of these four wearing a different name.

Patterns

One fill per screen

Exactly one filled button visible at any moment. Ghost everything else. The fill marks the single next action.

Emphasis is a 3px left rule

When something needs to be louder than its neighbours, it gets --edge-emph on the left, not a bigger shadow or a brighter fill. Consistent across next-up steps, checkpoint cards and the quiz teaching panel.

Repeating content is a list

Three or more sibling items of the same kind go in one card as hairline rows. Cards are for distinct things, not for each item in a set.

Emoji

Not in titles, section headers, result screens, or path step rows. Kept where they are genuine wayfinding — the dashboard topic grid, where an icon per topic aids scanning a large set. Everywhere else they undercut the typography that does the work.

Jyutping

Every Chinese string is immediately followed by jyutping. Tone colouring is applied per-syllable by colorJyutping() and never by hand.

我好餓，想食點心。

One progress indicator per screen

The contextual hairline tracks stage progress, not whole-path progress. Two bars measuring different things a centimetre apart is the single biggest source of incoherence in the current build.

Responsive

Centred single column, not desktop layouts. Content caps at --measure (680px) and centres; prose caps at --measure-text (68ch). Grids are auto-fill minmax() so they reflow without media queries. Header, contextual row and docked bar all constrain their inner content to --measure while their backgrounds span full width.
