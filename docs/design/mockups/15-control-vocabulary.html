15 · Control vocabulary Dashed ring = the --tap-min area. Red where the control is smaller than it.

1 · Where we are — one control, seven sizes

The circular play/mic control appears in seven places and is a different size in each. Nothing decided this; each screen picked a number. Six of the seven are smaller than --tap-min, which DESIGN_SYSTEM §1.2 defines as the minimum smaller dimension of anything interactive, including header icons.

2 · The separate question hiding inside this one

Painted size and touch target are not the same thing. A 32px circle can carry a 44px hit area — the extra region is invisible and costs no layout. So "must every control be 44px across?" is really two questions: how big should it look, and how big should it respond. The second has one right answer. Only the first is a matter of taste.

Painted 32px, target 32px

Today's conversation bubble. Compact, but it misses the target rule and is genuinely fiddly next to a thumb.

Painted 32px, target 44px

Same appearance, compliant target. One extra rule — ::after at 44px, centred, invisible.

Painted 44px, target 44px

Compliant by construction, nothing to explain — but it is a visibly heavier object in a dense row.

3 · The four contexts where the choice actually bites

Each context below is rendered four ways: as it is today, then under three vocabularies. A paints everything at 44px. B allows two painted sizes, 32 and 44, with the target always 44. C allows three, 28 / 36 / 44, target always 44. Turn on the tap-target overlay to compare them honestly.

4 · The header icon is not part of this decision

Worth separating out: .header-info-btn is 34px with a visible hairline ring, but styleguide.html already specifies header icons as a 44px transparent host with a 17px glyph and no ring. So the header is not an open question — the code simply never conformed. Whichever option below wins, this one is a straight fix.

Today — 34px, ringed

The ring makes it read as a button in a bar where nothing else is outlined, and it misses the target rule the same section names.

5 · The labelled controls — a mapping, not a choice

Separately from size, eight labelled controls are hand-rolled versions of primitives that already exist in styleguide.html but were never ported into styles.css. These are not really a design question — they are the same control drawn slightly differently in each place. Shown here so the visual shift is visible before it happens, since a few do change weight.

6 · What each option costs

OptionPainted sizesMeets §1.2Consequence
A44 onlyyes Simplest rule in the system — one number, nothing to remember, no hit-area mechanism. But the conversation view gains a row of heavy circles beside short bubbles, and the checkpoint review list goes from a quiet column of text to a column of buttons. Most likely to need a density fix later.
B32 · 44yes Keeps today's visual hierarchy where it is doing work — play is secondary inside a bubble, primary beside a sentence — while making every target legal. Costs one mechanism, .pc--hit, which must be understood or it looks like dead CSS. Two sizes is few enough to stay memorable.
C28 · 36 · 44yes Preserves the most nuance and requires the fewest judgement calls when migrating, since most current sizes round to a neighbour. But three sizes is close enough to today's seven that the next screen will plausibly invent a fourth — it concedes the principle that made the rule worth having.
Not shown as an option: leaving it. Six of seven controls miss a rule the design system already states, and .play-mini at 28px sits in the checkpoint review list — the screen a learner uses while getting things wrong, which is the worst place for a control that is hard to hit.

7 · What this does not settle

Three things stay open regardless of which option wins, and none of them block it: the speak-mode mic is 76px with a tinted fill and is deliberately a hero control, not part of this family; .translate-mic and .play-mini use --brand rather than --brand-edge for their border, which is a separate inconsistency worth folding in whichever way this goes; and .sentence-note still carries rgba(183,134,30,…), the retired CP_GOLD hue, which is a colour decision rather than a control one.
