2 · Why C, and what it costs

The complaint has a structural half and a cosmetic half, and only C answers both. Repainting the chooser (A, B) fixes the visual echo but leaves a two-up selector sitting on a three-up selector — the thing that reads as a hierarchy between two axes that are unrelated. C stops the tier being a selector, so the question of what its selected state looks like never arises.

It also makes both routes speak the same grammar. Option X already settled that in path context the meta line states the tier as text and the move lives elsewhere, named. C is the same sentence with the move inline instead of at the foot — state on the left, one named offer on the right. What C costs, stated plainly. With three or more tiers it stops working — "Switch to Tier 2" has no room for a third target and would need a chooser after all. Today the maximum is two and the schema is only ever populated with [1] or [1, 2], so this is a real but currently theoretical limit; it is worth a line in the register rather than designing around now. The second cost is smaller: C's offer is a text button with an arrow, and the app has no other inline text action of that kind, so it is one genuinely new component — .tier-offer — even though it needs no new state language.

One question I would put back to you rather than settle. C's offer is drawn in --brand, which makes it the only brand-coloured interactive thing above the subtabs. The alternative is --muted-dark with a brand arrow, which is quieter but drops close to the word count beside it and may not read as tappable at all. Both are defensible; the brand version is drawn because an offer that nobody notices is the same as option L, which was not what was chosen.
