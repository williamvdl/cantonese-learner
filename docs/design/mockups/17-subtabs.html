The topic subtabs never made it onto the primitive layer. They are the last piece of mockup 04 — the reference page the whole design system was derived from — still rendering its pre-system treatment. Three divergences, and one of them has a forward cost.

What's built versus what mockup 04 drew

The active state is the one that costs something today. A solid fill on a tab selector spends the screen's one filled element on a selector rather than an action (§3.1) — on the Learn screen it is the loudest thing present, and it isn't the thing to do next. Mockup 04's 2px rule says "you are here" without claiming to be the action.

The forward cost: the styleguide's Tab bar note already promises the phase 6 tab bar will use "brand plus a 2px top rule — same emphasis language as the topic subtabs." Against the built code that sentence is false. Phase 6 would have either copied the boxed fill, or built the 2px rule and left the subtabs disagreeing one tap away.

Why this is one primitive, not two components

The same treatment on the phase 6 tab bar, for comparison — the rule moves to the top edge because the bar sits at the bottom of the viewport, but the colour, weight and 2px rule are the same declaration. A shared primitive with a --top modifier covers both; building the subtabs alone now and the tab bar later would write the emphasis language twice and invite them to drift apart, which is exactly how the subtabs ended up here.

Carried over on port

The tap target must be declared, not implied. Mockup 04's .subtab computes to roughly 27px — a 14px line box plus 12px of bottom padding. Transcribing it would take .subtab-btn from a 42px miss to a 27px one, and because the height would come from padding rather than a declared min-height, standing check 2 would report it clean. Both options above declare min-height: var(--tap-min) explicitly. This is the stage-stepper defect from v109, one component along.

Retires: .subtab-btn's border, background and radius — three declarations that exist only to make each tab a box. .subtab-btn also leaves BACKLOG.md's sub-44px list, taking it from three declared misses to two.
