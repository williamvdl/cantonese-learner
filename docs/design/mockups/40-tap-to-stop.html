Tap to stop, then a short wait

Why this exists. Speaking is moving from the browser's listener to Azure (IN_PROGRESS, "the listening cut-off"). Two things change for the learner, and only two. Nothing stops the recording but them — no more being cut off at a pause, but also no automatic finish. And there is no live text while they speak: the words arrive after Stop, typically under a second later (median 0.83 s on the Pixel, worst 1.5 s). Everything else on the speak card — the sentence, the "You said" line, the result panels, the breakdown — is unchanged and is shown here only for context.

Scope, settled 2026-11-03: all four speak surfaces switch together (they share one listening function); with no speech key the app keeps the browser's listener, unchanged; the key is entered in Settings, stored on the phone only. Frames use the Learn "Say it back" sheet; Chat, the checkpoint review and Translate reuse the same card contents (DES-40), and the checkpoint keeps its milestone palette exactly as it does today.

new marks what this mockup adds. unchanged marks what is shown only for context. One genuine choice is offered as two options, MOCK-40-A and MOCK-40-B; everything else is a single proposal.

1 · The flow, start to finish (with MOCK-40-B's level meter)

Four states, as today: idle, recording, checking, result. Checking is the one new state, and it is short. Recording and checking are the same height, so nothing on screen moves while the learner waits; the result then grows the card exactly as it does today.

2 · The one real choice: what replaces the live text

Today the words appear as you speak, which also quietly tells you the mic is working. That goes. If nothing replaces it, a dead mic (permission revoked, another app holding it) is only discovered after Stop, as "I didn't catch anything". MOCK-40-A adds the minimum; MOCK-40-B adds one small new primitive to keep that reassurance.

MOCK-40-A · Timer only

0:04 · press Stop when you've finished

For: no new primitive at all; the pulsing mic already says "recording". Against: the pulse is decoration — it pulses whether or not any sound is arriving, so it cannot tell a working mic from a silent one.

MOCK-40-B · Timer + level recommended

0:04 · press Stop when you've finished

For: it moves only when sound arrives, so it is the one honest signal that the mic hears you — what live text used to give for free. Cost: one primitive, .speak-level, five bars driven by the recording's own input level; no new colour (it takes the live red).

MOCK-40-B · Level while you pause

0:07 · press Stop when you've finished

During a pause the bars settle low while the timer keeps running. That is the new behaviour made visible: silence no longer ends anything. The learner can see they are still being recorded.

3 · When it does not go to plan

Four cases. None uses the error red, because none is a wrong answer (§4): nothing heard is absence (muted, like a missing syllable in the breakdown), and a failed connection is not the learner's doing at all. Each has exactly one filled button (§3.1).

Nothing heard new copy

I didn't catch anything.
Check the mic isn't covered, then try again a little closer.

Azure returned no words. Uses .speak-result-close, the neutral panel, not a mismatch: there is nothing to compare, so no verdict is stated. Recorded as nothing, never as a wrong attempt.

Can't reach the checker new copy

Couldn't check that one.
The speech checker didn't answer — check your connection. Your attempt wasn't marked either way.

No network, a timeout, or Azure refusing the key. It says plainly that the attempt was not graded, so a learner never reads silence as failure. Try again records afresh; it does not quietly switch to the browser's listener mid-attempt. When Azure refuses the key, trying again cannot help, so the second line reads instead: Your speech key wasn't accepted — check it in Settings.

The 30-second stop new rule

You said:
✓ Great! You said it correctly.

Stopped automatically at 30 seconds.

A safety stop, so a forgotten Stop cannot record on indefinitely — and it keeps every clip well inside the 60-second limit of the short-audio fallback. The longest real attempt so far was under 10 seconds, so 30 leaves room for slow, paused speech. The clip is checked as normal, with one muted line saying why it ended.

No speech key: browser's listener one line

Press the mic and say the line above

Using the browser's listener, which may stop when you pause. Add a speech key in Settings to fix that.

The fallback, settled: with no key, everything works exactly as it does today, and this one muted line replaces the "take your time" line from frame 1 — because on this path, pausing will cut you off.

4 · Settings: the speech key

A second .set-row in the existing Settings sheet, below Audio speed. The sheet is sized to its contents (MOCK-19-sheet), so it simply grows by one row. The key is stored on the phone only, like the Gemini key on Translate. Proposed: on Save the key is checked straight away with a tiny request that uses no audio, so a mistyped key is caught here rather than on the first sentence. Whether the browser can make that request is confirmed at build time; if it cannot, the first sentence catches a bad key instead, through the "Couldn't check that one" panel.
