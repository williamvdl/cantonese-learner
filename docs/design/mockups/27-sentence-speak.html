Sentence speak feedback — where it lives, what Chat does, and the forgiven near-miss

Mockup 27, for DES-38 and DES-39. Scope is settled and not reopened here: sentences only, never a tone verdict. renderSpeakBreakdown() already does the per-syllable alignment — every option below reuses it and the existing .sheet primitive rather than inventing either. Phone frames are 412px wide — Pixel 10's own CSS viewport, not an arbitrary mockup width; see the new note in DESIGN_SYSTEM.md §8, which makes this the standard going forward.

found while checking the premise

§3's open question was written as "the breakdown only renders on mismatch." That's not what the shipped code does. I ran renderSpeakBreakdown() against the exact v129 example — 我食咗飯，仲飲咗茶 (ngo5 sik6 zo2 faan6, zung6 jam2 zo2 caa4) heard back as 中 (zung1) for 仲 (zung6) — through the live fuzzyMatch() and render.js's status === 'matched' branch. It is forgiven (fuzzyMatch returns true), and the breakdown does render — Chat already shows the learner that 仲 came back as 中. So the near-miss isn't silently hidden today. What actually happens is worse than either "shown" or "hidden": the correct-syllable green frame and the wrong-syllable red character render together, in the same box — see the first panel in §3. A green "you got it right" panel containing a red "wrong" mark is confusing on its own terms, and colouring the differing syllable --feedback-bad (the same red used for genuine quiz mistakes) reads as a verdict, which is the one thing DES-38 says this feature must never state. §3 below is reframed accordingly — not "should it show," but "what does showing it without contradicting itself or implying a verdict look like."

CostWhat it gets rightWhat it gets wrong
A · Sheet New §2 entry + styleguide section — but the host (.sheet-wrap/.sheet-scrim/.sheet) is already built and battle-tested by Settings. The work is content, not machinery. A recording is a focused, single action against a dimmed backdrop — the scrim says "this is the only thing happening right now," which matters when the mic is listening. Closing returns to exactly where you were in the sentence list. One more surface for the design system to carry, even if the host already exists.
B · Inline No new primitive — reuses the chip-expands-a-panel idiom .s-chip-bd / .s-chip-note already established. Cheapest to build. Stays on one scroll position, same as the other two chips. A chip today means "reveal information I already have" — tapping it never asks for a device permission or starts an unmutable action. A mic chip breaks that contract, and if a learner opens speak on two sentences in a row without collapsing the first, the page grows two live mic panels stacked in a scrolling list — recording is not a browsing action and shouldn't compete with browsing for space.

Recommendation: A. The sheet's real cost was already paid when Settings was built — this is the second consumer of a primitive that exists for exactly this shape of problem (one bounded, focused action layered over a screen you return to). B is cheaper to build but bends an existing idiom (disclosure chip) to cover an action it wasn't designed for, and idioms that get bent quietly are how .cp-optional ended up a sentence styled as a chip.

Recommendation: keep Chat's screen as it is. The two contexts aren't the same shape. A Learn sentence is one independent item in a flat list — that's exactly the "bounded action over a backdrop you return to" the sheet is for. A Chat walk is inherently sequential: turn-taking between two speakers, a running "Line 3 of 8" position, an auto-advance on match. Forcing that into open-close-open-close against the sheet would mean re-deriving, inside the sheet, the sequence state the dedicated screen already owns for free — and losing the "where am I in the conversation" context between each open. Reuse belongs at the content layer — same renderSpeakBreakdown(), same mic control, same result treatment — not at the surface layer. That is what DES-38 already asked for, and forcing one surface onto two different-shaped problems is how the topic subtabs stayed unconverged for four phases.
