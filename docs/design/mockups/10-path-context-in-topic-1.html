The current renderPathBanner puts "Next step →" at the top of the screen, before the lesson has been done. These four states go at the bottom instead, where a lesson actually ends. The next target correctly reads a checkpoint when one is next — that logic already exists in getPathContext().

3 · Standalone entry — the same shell, degraded

A topic opened from the dashboard grid has no path. getPathContext() already returns null there, so the difference is purely presentational — and the shell should not change shape.

The rule that makes this work

One progress indicator per screen. The contextual hairline shows stage progress, not whole-path progress — so it moves visibly as you work through five topics rather than creeping 2% per lesson across 41. The old banner's separate .path-bar is retired; two bars measuring different things a centimetre apart is the single biggest reason the current screen feels incoherent.

Framing: stage, not path

getPathContext() currently returns step: 8, total: 41 and no stage. "Step 8 of 41" is technically true and motivationally awful. Every option here uses 3 of 5 in Building Sentences instead, with the path name demoted to the eyebrow. Stages are already in learning_paths.json and getStage() exists, so this is a few lines added to the context builder, not new data.

Back target

Back goes to the path timeline and is labelled with the stage name — because that's the part of the timeline you came from and want to land on again. Labelling it "Beginner Path" is accurate but drops you somewhere you have to re-find your place in.

Where I'd land

B (stage stepper). It's the only option that answers "where am I" and "what else is in this stage" in the same 44px, and the nodes are real navigation — tap to jump between sibling topics without going back to the timeline. It also makes the checkpoint visible from inside the topic as the diamond at the end of the strip, which is the thing that makes a stage feel like a unit with an end.

C (ribbon) is the safer pick if the stepper feels busy — same information, no tap targets, less to build. A is the minimum that still works. D costs nothing but loses the word count, and the eyebrow gets long enough to wrap on a narrow phone.
