Recogniser numerals — 29

Reported from a device on 2026-09-03 against the sentence 我生日係三月十號 (ngo5 saang1 jat6 hai6 saam1 jyut6 sap6 hou6), “My birthday is the 10th of March.” The learner said it correctly. Chrome on Android transcribed it as 我生日係3月10號, writing the spoken numbers as digits. Both faults below follow from that single transcription habit, and both were reproduced from the live code, not inferred from the screenshot.

The fold is where this starts measured

normalizeChinese() already folds digits to Chinese numerals (DES-46) — but per digit, so 10 becomes 一零 (jat1 ling4) rather than 十 (sap6). Its comment gives the reason: getting place value right “would need to know the target”. That premise is wrong, and the corpus says so. Every one of the 24 distinct numeral runs across the 101 corpus lines that contain one is a value form — 十一, 三十五, 四十, 一百, 一百八十, 二百, 五百, 一千. There is not a single digit-string reading (no 二零一零-style year, no phone number), so there is nothing for the target to disambiguate. A value-aware fold needs no target at all.

The second one matters more than it looks. DES-43 settled that for an audience assumed not to read Chinese, a character with no jyutping is not partial information, it is no information — and it set the coverage target at ~100% for exactly that reason. Digits were never in scope of that check, so a gap re-opened underneath it. The jp-unknown “?” marker that DES-41 added as the honesty rule doesn’t fire either, because the character is skipped before the lookup rather than failing it.

§1 — The fold fix, which is not a choice

Value-aware folding of 1–4 digit runs. Runs of 5+ digits keep the per-digit fold, because those are the case where a value reading really would be a guess (a phone number is read digit by digit). Verified against all 21 forms below, which include every multi-character run the corpus uses.

One residual gap, not fixed here, deliberately open question

兩 (loeng5) is the second most common numeral in the corpus, 12 occurrences, and a value fold of 2 produces 二 (ji6), not 兩. The digit 2 is the recogniser declining to choose between them, so this is a transcription ambiguity rather than a learner error — but there is no probe data showing the recogniser actually returns 2 where 兩 was said, so building a rule for it now would be guessing at a problem that may not exist. Proposed: leave it, and let a device session tell us. Worth knowing it is there, because if it does bite, it will look exactly like the 十 fault above.

The heard line shows the folded characters. The argument for it is that this is more faithful, not less: speech contains no digits. Writing 十 as 10 is a transcription convention the recogniser chose, so undoing it recovers what was said rather than editing it. Every glyph on the line is then something the learner can read back and pronounce. Against: “You said” is no longer byte-for-byte the transcript, so if the fold is ever wrong the app misquotes the learner — and it is the only place that would show it.

§3 — Recommendation

MOCK-29-B, the folded form, and the reason is the audience rule DES-43 already settled rather than a fresh preference. A learner assumed not to read Chinese cannot do anything with 3月10號: the digits are unreadable as Cantonese and the jyutping line under them is the only route to the sound. Option A leaves a line whose glyph count and syllable count disagree with no way to tell which digit owns which syllable, which is the same “partial information is no information” problem DES-43 rejected, just smaller.

The case against B is real and worth stating rather than waving past — it is the only surface that quotes the learner, so a wrong fold misquotes them. That risk is bounded by §1: the fold is exact for every form the corpus contains, and 5+ digit runs stay per-digit rather than being guessed at. If B is chosen, the safer build is to fold for display using the same single function the comparison uses, so the two can never drift into disagreeing about what a number was — which is the failure mode that would actually hurt.

If neither appeals, there is a third shape not drawn here because it costs more than it returns: show both, e.g. “You said: 我生日係三月十號 (heard as 3月10號)”. It is honest and it is also clutter on a line that already carries a character row and a jyutping row.
